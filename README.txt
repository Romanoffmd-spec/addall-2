AddAll 2.0: локальная платформа клинических регистров
=====================================================

ЗАПУСК
1. Распакуйте папку addall-2 в любое место (например, Документы).
2. Откройте файл index.html в Chrome или Edge (двойной клик).
3. При первом запуске создайте администратора.
Интернет и сервер не нужны.

ГДЕ ХРАНЯТСЯ ДАННЫЕ
Данные хранятся в браузере на этом компьютере (IndexedDB), отдельно для каждого браузера.
Если очистить данные браузера, они удалятся. Поэтому:
- регулярно делайте резервную копию: «Пользователи и настройки» → «Скачать резервную копию»;
- файл копии содержит персональные данные пациентов, храните его на защищённом носителе;
- перенос на другой компьютер: резервная копия → «Восстановить» там.

ОБНОВЛЕНИЕ 25.11.2026 (локальная версия)
- Если пациент умер раньше срока ожидаемой формы, очередь показывает «умер до срока: внесите исход». Внесите исход, иначе показатель считает случай неизвестным.
- Запись с номером эпизода, которого нет в регистре, отмечена красным на таймлайне и не даёт выпустить официальный отчёт за период.
- Исправлены ошибка отрисовки «Отчётного периода» и подсчёт показателей по формам со сроком.
- «Паспорт регистра» (меню «Работа»): ответственные, цель, правовое основание, критерии включения, место хранения и автоматический чек-лист готовности. Отсюда же скачивается публичная страница результатов из официального отчёта.
- «Сравнение учреждений и врачей»: доля с поправкой на надёжность, чтобы малые учреждения не становились лучшими или худшими случайно.
- «Сведения о смерти»: загрузка списка умерших (ИИН или № ИБ и дата), предпросмотр, спорные строки проверяются вручную.
- Новый шаблон регистра «Безопасность препарата или изделия».

ЧТО ВНУТРИ
- Конструктор регистров: формы событий, разделы, поля 10 типов, условия показа, формулы, словарь определений, версии схемы.
- Шаблоны: пустой, колоректальный рак (ICORC/ICHOM, LARS, Wexner), хирургический аудит.
- Карточка пациента на весь экран, таймлайн событий, полнота данных, история изменений, документы (выписка, письмо).
- Осложнения по Clavien-Dindo с автоматическим CCI, ИМТ, возраст, койко-день, модели риска через logit().
- Показатели качества с целями, бенчмаркинг хирургов и центров под кодами.
- Аналитика: когорты, распределения, кросс-таблицы с χ², контрольные карты Шухарта, Каплан-Майер с лог-ранговым критерием,
  RA-CUSUM, VLAD, funnel plot (с поправкой на риск), показатели по годам. Экспорт графиков SVG/PNG и данных CSV.
- МДК: заседания, повестка, клинические данные подтягиваются из регистра, протокол для печати.
- Опросники (PROMs): расписание от события, назначение автоматически, отправка через WhatsApp/email, режим заполнения пациентом.
- Годовой отчёт регистра с результатами по хирургам, печать в PDF.
- Импорт из CSV/Excel с сопоставлением столбцов и проверкой, экспорт широкой и длинной таблицы, с псевдонимизацией.
- Роли (7), права, журнал аудита всех действий и входов, мультицентровость.

КАБИНЕТ АДМИНИСТРАТОРА
Откройте сервер AddAll, войдите как администратор и выберите «Администрирование → Кабинет администратора».
- «Заявки»: подтверждение и отказ, очередь доступа к отдельным регистрам, временные пароли.
- «Пользователи»: поиск по имени, логину, учреждению или номеру заявки. Роль, срок действия, отключение и завершение сеансов.
- «Регистры и доступы»: создание, импорт схемы, выдача и отзыв индивидуального доступа, архив и восстановление.
  Пустой регистр удаляется из архива после ввода названия. Регистры со связанными данными остаются в архиве.
- «История»: решения по заявкам и административные действия.
Сотрудник регистрируется по тому же адресу сервера. После сохранения сервер показывает номер заявки. Статус можно проверить через вход
с указанным логином и паролем. Если открыть index.html как файл, учётная запись хранится только в этом браузере.

ВЫГРУЗКА РЕГИСТРА
«Импорт и экспорт → Комплект регистра» выгружает XLSX, ZIP с таблицами CSV или JSON. Фильтры: период, учреждение, поля и черновики.
В кодированном режиме сохраняются связанные коды пациентов, эпизодов и событий. Прямые идентификаторы исключаются, даты заменяются
относительными днями. Остаются все повторные визиты и вложенные поля, причины пропусков, ответы анкет и словарь с версиями.
Идентифицируемый комплект выбирает администратор. Схема отдельно переносится через JSON, при импорте создаётся черновик.

ПРИЁМ ДОКУМЕНТОВ
AddAll рассчитан на работу без интеграции с МИС. Выписки поступают из общих папок или через браузер. Для сверки охвата
используются независимые журналы и списки в CSV/XLSX.

На SQLite-сервере настройте локальную модель Ollama и, если есть доступ к папкам, задайте путь к файлу настроек:
    $env:ADDALL_INTAKE_MODEL = 'имя локальной модели, установленной в Ollama'
    $env:ADDALL_INTAKE_SOURCES = 'D:\AddAll-config\sources.json'
    node server/server.js

Файл sources.json в UTF-8 содержит по одной записи на каждую папку:
    [
      {"directory":"D:/AddAll-Test-Inbox","registryId":"ID регистра","center":"Учебное учреждение","name":"Выписки"},
      {"directory":"//fileserver/department/export","registryId":"ID другого регистра","center":"Другое учреждение","name":"Журнал отделения"}
    ]
Для одной папки по-прежнему работают ADDALL_INTAKE_DIR, ADDALL_INTAKE_REGISTRY и ADDALL_INTAKE_CENTER. После изменения путей
перезапустите сервер. Служебной учётной записи AddAll нужен доступ на чтение каждой папки. Папки размещаются отдельно от каталога базы.
В папках используйте «№ ИБ/файл» или «№ ИБ/внешний номер эпизода/файл». Документы в корне появятся без предложения пациента.
Состояние каждой папки видно в «Работа → Документы из хранилища». Папка проверяется примерно каждые 15 секунд.

В том же разделе «Загрузить документы» принимает до 20 файлов за раз, в том числе при отсутствии настроенных папок. Укажите регистр
и учреждение. № ИБ и внешний номер эпизода относятся ко всем выбранным документам. Для разных пациентов оставьте номера пустыми.
У каждого файла свой результат. Можно повторить загрузку после обрыва. При совпадении регистра, учреждения, пациента, эпизода и
содержимого одинаковый файл из папки и браузера обрабатывается один раз. Оригиналы сохраняются в incoming-files рядом с SQLite.
Текст и поля можно сверить рядом. После подтверждения они сохраняются в черновике. Исходные папки открываются только для чтения.
Поддерживаются TXT, DOCX, PDF, JPEG, PNG и WebP, до 25 МБ. Для фото и сканов нужен ADDALL_INTAKE_VISION_MODEL. Чтобы разобрать
PDF-скан, серверу также нужен pdftoppm в PATH или явный путь ADDALL_PDFTOPPM. OCR требует сверки с оригиналом.

АВТОМАТИЧЕСКАЯ РАССЫЛКА ОПРОСНИКОВ
Одноразовые ссылки работают на SQLite-сервере. Автоматическая отправка отключена, пока не заданы ADDALL_SURVEY_GATEWAY (HTTPS-адрес
шлюза клиники), ADDALL_SURVEY_PUBLIC_URL (адрес AddAll, доступный пациентам) и ADDALL_SURVEY_GATEWAY_KEY (секрет шлюза, от 32 символов).
После согласия пациента отправляется ссылка на назначенный опросник по email или SMS. Одно напоминание через 7 дней, если ответа нет.
Шлюз принимает POST с channel, to, text, link, reminder и обязан учитывать заголовок Idempotency-Key. Для проверки используйте тестовый шлюз.

ИИ-ЗАПОЛНЕНИЕ ИЗ ДОКУМЕНТОВ
- В любой форме события и в карточке пациента кнопка «Заполнить из документа (ИИ)».
- Источник: вставленный текст, DOCX, TXT, PDF с текстовым слоем и фото документа при поддержке моделью.
- Заполненные ИИ поля подсвечиваются жёлтым, рядом цитата-доказательство из документа. Всё проверяет врач перед сохранением.
- Если ИИ не нашёл дату события, укажите её вручную или пропустите событие. Цитаты к принятым значениям после сохранения можно открыть в форме события в разделе «Цитаты из документа».
- Настройка: «Пользователи и настройки» → «ИИ-ассистент».
  Локально (данные не покидают ПК): установить Ollama, выполнить «ollama pull qwen2.5:7b».
  Если браузер не может подключиться, задайте переменную среды OLLAMA_ORIGINS=* и перезапустите Ollama.
  Облачно: Claude API (ключ Anthropic) или любой OpenAI-совместимый сервер, например будущий сервер ННОЦ.

ВЕРСИЯ 2.1: ДОБАВЛЕНО
- Модели риска: CR-POSSUM (Tekkis 2004) и P-POSSUM/POSSUM (Prytherch 1998, Copeland 1991). Готовый блок полей
  добавляется в любую форму («+ Блок модели риска» в конструкторе), прогноз используется в RA-CUSUM, VLAD, funnel plot.
- Запросы по данным: значок ⚑ у поля, переписка, закрытие; верификация с первичной документацией (SDV);
  блокировка проверенных событий, разблокировка только с причиной в журнале аудита. Раздел «Запросы по данным».
- Клинические исследования: протокол, критерии включения/исключения, блочная стратифицированная рандомизация
  со скрытой последовательностью, визиты с окнами, журнал скрининга, схема CONSORT, экспорт для статистика.
- ИИ: разбор целой выписки сразу на пациента и несколько событий («Пациент из документа», «Разобрать документ»).
- Шаблоны: TNT рак прямой кишки, латеральная лимфодиссекция, грыжи (EHS), бариатрия (%TWL, %EWL).
- Резервные копии с шифрованием AES-256 по паролю. Автовыход при бездействии.

ОГРАНИЧЕНИЯ ЛОКАЛЬНОЙ ВЕРСИИ
- Один компьютер = одна база. Совместная работа нескольких врачей появится после переноса на сервер ННОЦ.
- Пароли защищают от случайного доступа, но не от человека с доступом к этому компьютеру.
- Опросники по ссылке пациенту (без участия врача) требуют сервера; сейчас отправка текстом в WhatsApp/email.

ВЕРСИЯ 2.3: РЕГИСТРАЦИЯ СОТРУДНИКОВ
- На странице входа две вкладки: Вход и Регистрация.
- Регистрация: ФИО, отделение (из списка учреждения), должность, год и специальность резидентуры, центр, телефон, ORCID, роль, запрошенные регистры, логин, пароль с проверкой надёжности, обязательство о конфиденциальности.
- Заявка ждёт администратора: Администрирование, блок «Заявки на доступ». Администратор подтверждает роль, отделение, куратора и доступ к регистрам или отклоняет заявку. О новых заявках сообщает колокольчик.
- Доступ к регистрам: если у пользователя отмечены регистры, он видит только их. Ничего не отмечено: все регистры.
- «Забыли пароль?»: заявка уходит администратору, он задаёт временный пароль, при входе система попросит сменить его.
- Меню пользователя: «Мой профиль» (данные, отделение, смена пароля).
- Список отделений и включение саморегистрации: Администрирование, карточка «Учреждение».

ВЕРСИЯ 2.4: ДОСТУП К РЕГИСТРАМ ПО ОТДЕЛЕНИЯМ
- У каждого регистра есть отделение-владелец. Сотрудник после подтверждения видит регистры своего отделения, администратор видит всё.
- Видимость регистра (вкладка «Доступ» в регистре): только отделение-владелец, всё учреждение или только приглашённые участники.
- Регистры других отделений видны в разделе «Регистры» только названием, данные закрыты. Кнопка «Запросить доступ» отправляет запрос владельцу.
- Создатель регистра, администратор и руководитель отделения-владельца одобряют запросы и сами приглашают участников, в том числе из других отделений и центров.
- Прямая ссылка на чужой регистр или пациента показывает «Нет доступа» с кнопкой запроса.

ВЕРСИЯ 2.5: ФУНКЦИИ ПО ОБРАЗЦУ DENDRITE INTELLECT WEB
Форма события
- Закреплённая шапка: пациент, № ИБ, дата рождения, пол, статус, владелец записи.
- Страницы: Назад / Далее, список страниц, «Страница 2 из 4», переключатель «Вся форма сразу».
- Сводка: все ответы; «Не заполнено» красной ссылкой ведёт к вопросу, затем «Вернуться к сводке».
- Поле с зелёной полосой заполнено, с серой нет; обязательные подписи красные.
- Правила ввода красным под полем и напоминание в начале раздела (задаются в конструкторе).
- Вложенные записи (тип поля «Вложенные записи»): например, анастомозы внутри операции, швы внутри анастомоза, до 3 уровней. В формулах: count(), sumOf(), anyOf().
- Выбор хирурга: «Я и недавние» вверху, «Приглашённый хирург», «Хирург, не зарегистрированный в системе».
- Новый случай: полоса «Проверьте пациента».
Пациенты
- Цвет строки: зелёная: полная запись, жёлтая: неполная или черновик, красная: умер. Фильтр, в том числе «просрочены анкеты».
- Тип идентификатора, ИИН, источник оплаты, статус и дата смерти, согласие на анкеты.
- Анкеты при ретроспективном вводе: из прошедших точек отправляется только последняя и сразу.
Делегаты: врач назначает, кто вносит данные за него; подтверждение раз в год (Работа → Делегаты). В форме поле «Владелец записи».
Учебный режим: отдельная база с вымышленными пациентами и генератор пациентов (Работа → Учебный режим).
Безопасность: блокировка на 15 минут после 3 неверных паролей, срок действия пароля и учётной записи, сообщение дня на главной, счётчики на странице входа.
Наука → Отчёт хирурга: объём, операции в год против рекомендуемого минимума, исход с 95% ДИ против регистра, правило «сигнал / выброс», койко-дни, полнота; публикация в HTML и сертификат участника для аттестации.
Аналитика: XmR (с поиском сдвига), таблица дожития (актуарный метод), хронологии пациентов с интервалами, несколько когорт на одном графике.
Работа → Экспорт моих данных: Excel с листами пациентов, каждого события и каждой группы вложенных записей.
Наука → Документы регистров: бумажная форма для печати, краткая инструкция, загрузка протоколов и согласий.
Карточка пациента → Файлы → «Схема»: рисунок поверх схемы (толстая кишка, брюшная стенка, таз) или своего изображения.
Администрирование → Запросы субъектов данных: журнал обращений по персональным данным со сроком ответа 30 дней.
Уведомления: подтвердить делегатов, неполные записи, резервная копия старше 7 дней.

ВЕРСИЯ 2.6: ВТОРОЙ ПАКЕТ (по видео-инструкциям Британского общества герниологов к системе Dendrite)
Форма события
- Вкладки внутри страницы: раздел с отметкой «вкладка» показывается на одной странице с предыдущим, кнопка «Следующая вкладка».
- При уходе со страницы с пустыми обязательными вопросами появляется предупреждение; о пустых желательных напоминает подсказка.
- Цвета: серый без ответа, зелёный отвечено, красный обязательный, оранжевый желательный; легенда в шапке формы.
- Двойной щелчок по «да / нет / неизвестно» очищает ответ. Вариант «нет» в множественном выборе гасит остальные.
- Выбор щелчком по схеме синхронно с вариантами: EHS для вентральных грыж, отделы толстой кишки, 9 областей живота, латеральные лимфоузлы таза.
- Поиск по длинным спискам (сетки, импланты) с запоминанием часто выбираемых.
- Перенос из прошлых записей пациента: отмеченные поля подставляются в новое событие.
- Хронология пациента: «⚠ не отвечено» по каждому пропуску, щелчок открывает событие прямо на этом вопросе.
Пациенты
- Сквозной ID пациента, несколько идентификаторов, сортировка по столбцам, по 25 на странице, поиск по ФИО, ID, № ИБ, дате рождения и дате операции.
- ФИО, дату рождения, пол и дату сохранённого события меняет только администратор; остальные отправляют «Запрос на исправление».
Шкалы: Charlson (с поправкой на возраст и 10-летним прогнозом), mFI-5, клиническая шкала хрупкости, ECOG и ASA.
Анкеты из библиотеки: боль ЧРШ, боль после грыжесечения, PHQ-2, GAD-2, Бристольская шкала, удовлетворённость, восстановление.
Новые шаблоны: «Вентральные грыжи (EHS)» и «Несостоятельность анастомоза (колоректальная)».
Импорт CSV: слияние с существующими событиями, дополнение карточек, режим проверки без сохранения.
Работа → Направления: направление, заочная оценка по списку, отправка на ближайший МДК, письмо направившему врачу в Word.
Доступ
- Срок учётной записи (например, 365 дней), самопродление учётной записи и пароля в «Мой профиль», напоминание за 14 дней.
- Новый пользователь от администратора меняет пароль при первом входе.
- Регистрация: рабочая почта обязательна (личные ящики можно запретить), телефон с кодом страны.
- Делегат: администратор указывает врачей, врач сам подтверждает делегата.
- На странице входа: справка, документы для всех, обратная связь. Обратная связь и запросы на исправление видны администратору.
Английский интерфейс: переключатель в меню пользователя и на странице входа (переведены меню, кнопки и основные экраны).

Версия 2.8: справочник учреждений, отделений и должностей
- Администрирование > Пользователи и настройки > "Учреждения, отделения, должности": администратор добавляет учреждения по мере подключения, внутри каждого свои отделения, и общий список должностей. - Первый запуск: указываются только своё учреждение и отделение, длинный список отделений убран.
- Страница очистки reset.html удаляет все данные в браузере.

Версия 2.9: режим национального регистра и сервер
1) Модули (Администрирование > Пользователи и настройки > Модули платформы)
- По умолчанию включено только ядро регистра: регистры и формы, пациенты и события, наблюдение, запросы по данным, полнота, аудит, аналитика, годовой отчёт, отчёт хирурга, экспорт, анкеты пациентов, делегаты, учебный режим, дашборд.
- МДК и направления, журналы, исследования и рандомизация, рукописи и литература, документы по шаблонам, ИИ включаются отдельно. Кнопки "Только ядро" и "Включить всё".

2) Сервер с общей базой (папка server)
- Нужен Node.js 22 LTS или новее (https://nodejs.org). Ничего больше устанавливать не надо.
- Запуск на Windows: двойной щелчок по start-server.bat. Или в командной строке: node server\server.js
- Открыть: http://localhost:8080. С других компьютеров сети: http://<адрес этого компьютера>:8080 (адрес пишется в окне сервера). Порт меняется так: node server\server.js --port=9000
- База хранится в server\data\addall.sqlite. Резервная копия: остановить сервер и скопировать этот файл.
- Что делает сервер: проверяет пароль и выдаёт сессию на 12 часов, блокирует вход после 3 ошибок, не отдаёт хэши паролей, отдаёт пациентов и события только тех регистров, к которым есть доступ, не даёт сотруднику поменять себе роль, не даёт удалять или менять журнал аудита.
- Если открыть index.html двойным щелчком, AddAll работает как раньше, локально в браузере, с отдельной базой. Учебный режим всегда остаётся в браузере.
- Для работы через интернет между больницами нужен HTTPS (сертификат) и размещение на сервере учреждения в Казахстане: это делает IT-отдел, приложение для этого уже готово.

Версия 2.11: честные показатели качества
- Плитки качества на главной больше не красят результат в красный или зелёный по одной цифре. Рядом с процентом показано "3 из 19" и 95% доверительный интервал.
- Зелёный (лучше цели) и красный (хуже цели) только когда весь интервал по одну сторону от цели. Иначе написано "не отличается от цели" и цвет нейтральный.
- Если случаев меньше 10, вместо процента крупно "3 из 7" и надпись "мало случаев для вывода".
- Видно, сколько случаев не вошло в расчёт, потому что поле показателя не заполнено.
- Дата расчёта и пометка "без поправки на риск".
- Нажмите на плитку (или на процент в аналитике и годовом отчёте): откроется список пациентов: у кого событие было, у кого нет, и у кого поле не заполнено. Из списка можно перейти в карточку.
- Если поле скрыто условием (например, степень ISREC, когда несостоятельности нет), случай теперь считается "без события", а не пропуском.
- Формулы проверены по первоисточникам и сверены с программой R. Исправлены две ошибки: в CR-POSSUM баллы за возраст (теперь 1 / 3 / 4 / 8, как у Tekkis 2004) и индекс CCI при осложнении степени V (теперь 100).
- Funnel plot: точные границы 95% и 99,8% по методу Spiegelhalter, с поправкой на риск по отношению наблюдаемых к ожидаемым (O/E), учёт избыточной дисперсии при 10 и более группах, вывод для каждой группы.
- Отчёт хирурга: статус по точному биномиальному критерию против регистра и ориентир лучших хирургов (метод ABC). Контрольный порог в процентах стал необязательным и показывается отдельно.
- Кросс-таблица 2 x 2: точный критерий Фишера. Манн-Уитни и Уилкоксон: точный расчёт для небольших групп. Каплан-Майер: доверительные интервалы.
- Цели показателей в шаблонах сняты, потому что у них не было источника. У показателя появилось поле "Обоснование цели"; если источник не указан, это видно в окне показателя.
- Исходы 30 дней (Работа): операции, у которых прошло 30 дней, а форма исхода не заполнена.
- Пакет к M&M (Работа): тяжёлые случаи за период, 5 случаев по 3 минуты, печать.
- У обязательных и желательных полей можно отметить "неизвестно", "не применимо" или "нет в документе".
- Несохранённый ввод в форме сохраняется в браузере и предлагается к восстановлению.
- Список пациентов: номер ID у всех пациентов, фильтры под заголовками колонок, сохранённые виды.
- Годовой отчёт на всю ширину экрана. Переходы между страницами и раскрытие групп в боковой панели стали плавнее.

Локальное обновление (24.11.2026)
- Поштучная сверка: в «Охвате регистра» загрузите CSV/XLSX из независимого журнала. Можно скачать шаблон, дополнить список
  или заменить его исправленной версией. Совпадение по внешнему номеру требует также учреждения и № ИБ. Для строк без внешнего
  номера используется дата. Видны совпадения, пропущенные случаи, ошибки входных строк и возможные дубли. Решения сохраняются.
- Отчётный период (Работа): проверка готовности, показатели, выпуск отчёта снимком; исправление выпускается новой версией с объяснением.
- Сроки наблюдения: оценка на 90-й день, сделанная раньше срока, за этот срок не засчитывается; можно выбрать «нужно к этому дню» для форм вроде патоморфологии.
- Очередь наблюдения (Работа): задачи создаются сами из настроек регистра (через сколько дней ожидается форма, повтор, окно). Можно заполнить форму или указать причину (не удалось связаться, отказался, наблюдается в другом центре, не применимо). Единицей учёта может быть и сам пациент: вариант «Пациент: длительное наблюдение» для регистров вроде диабета.
- Эпизод как единица учёта: в конструкторе выбирается событие, которое открывает случай (операция, диагноз, госпитализация). Охват, полнота наблюдения и показатели качества считаются по одним и тем же эпизодам. Форма может ожидаться в каждом эпизоде через заданное число дней; если её нет, случай виден как пропуск, а не теряется.
- Учебную базу можно открыть с первого экрана или через меню. Пошаговый гайд проходит по всем разделам (29 разделов): каждая кнопка и секция подсвечивается и объясняется. Есть оглавление для перехода к нужному разделу. Гайд можно повторить из верхней учебной полосы.
- Генератор доступен из конструктора и списка пациентов каждого учебного регистра. Есть выбор одного регистра или всех учебных регистров.
- Лист исходов 30 дней учитывает отдельные операции и дату подтверждения результата.
- В разделе «Работа → Охват регистра» можно сохранить сверку с числом из независимого источника.
- Серверная версия защищает новые пароли через scrypt и предупреждает о конфликте параллельных правок карточек, событий и опросников.
